# レビューJSON解析障害 恒久対応計画

**作成日:** 2026年8月24日
**対象:** AI Review Jenkins デモ版
**優先度:** P1（主要フローの回復性）

## 1. 背景

MR !12 の `REVIEW` ジョブで、Claude CLI は終了コード `0` を返したが、出力された
レビュー結果をJSONとして解析できず、ジョブが失敗した。

```text
agent returned invalid review JSON:
Expecting property name enclosed in double quotes
```

現状の再試行はCLIプロセスの異常終了だけを対象とし、終了コード `0` 後のJSON解析失敗は
再試行しない。このため、一時的な生成形式の揺らぎだけでレビュー全体が失敗する。

## 2. 目標

1. `REVIEW` と `RE_REVIEW` で、構文不正またはスキーマ不正の出力を再生成できる。
2. 再試行しても回復しない場合、原因を追跡でき、MR上で次の操作が分かる。
3. 生のエージェント出力や認証情報をGitLabコメント・通常ログに露出しない。
4. 成功時のFinding保存・GitLab Discussion投稿の既存挙動を変えない。

## 3. 対応方針

### 3.1 出力検証を実行成功の判定に含める

`run_agent` のプロセス終了コードだけでは成功と扱わず、レビュー結果については以下を
満たした時点で成功とする。

- JSONオブジェクトとして解析できること
- `findings` が配列であること
- 各Findingが投稿に必要なフィールド型を満たすこと

JSONの前後に説明文やMarkdownフェンスがある既存の許容範囲は維持する。

### 3.2 解析失敗時の再試行

- 対象イベントは `REVIEW` と `RE_REVIEW`。
- 解析またはスキーマ検証に失敗した場合、CLI異常終了時と同じ設定値
  `AGENT_MAX_ATTEMPTS` の範囲で再試行する。
- 再試行プロンプトには、JSONのみ・二重引用符・文字列内の改行と引用符のエスケープを
  明示し、レビューを改めて生成させる。
- 再試行回数を使い切った場合だけジョブを `FAILED` とし、既存の失敗通知を投稿する。

### 3.3 診断情報

- `event_type`、MR ID、試行回数、解析／スキーマの失敗種別、エラー位置をworkerログへ記録する。
- 生出力は既定で記録しない。障害調査が必要な場合だけ、長さを制限し、トークン・URL資格情報を
  マスクした診断ログを有効化できる設定を追加する。
- MRへの通知には生出力を含めず、再試行済みか・手動再実行方法のみを記載する。

## 4. 実施手順

| 順序 | 作業 | 完了条件 |
|---|---|---|
| 1 | 不正JSON（未エスケープ引用符、途中切れ、型不正）のフィクスチャとパーサーテストを追加する | 失敗形式ごとに期待する検証エラーを確認できる |
| 2 | レビュー結果の構文・スキーマ検証を、エージェント実行の再試行制御へ統合する | 1回目の不正JSON後に再実行される |
| 3 | 再試行専用プロンプトと安全な診断ログを実装する | 再試行理由・回数を追跡でき、生出力を露出しない |
| 4 | 成功、再試行成功、再試行枯渇の自動テストを追加する | `pytest` が全件成功する |
| 5 | workerイメージを再構築してデモ環境へ反映する | `worker` がhealthyで新イメージを使用する |
| 6 | 実GitLab MRで不正JSONフィクスチャと通常レビューをE2E確認する | 再試行・投稿・失敗通知が仕様どおりである |

## 5. 受入基準

- 1回目が不正JSON、2回目が正しいJSONのケースで、Findingが1回だけ保存・投稿される。
- 全試行が不正JSONのケースで、Findingを保存せず、ジョブが `FAILED` になり、次のキュージョブが継続する。
- 通常のレビュー、Markdownフェンス付きJSON、JSON前後の短い説明文は従来どおり解析できる。
- ログおよびGitLabコメントにアクセストークン、Git URLの資格情報、生のレビュー全文が出ない。
- 評価設計書の UC-14（システム失敗からの回復）をP1として合格する。

## 6. 展開とロールバック

- 実装後はworkerイメージだけを再構築し、`docker compose --profile agent up -d --no-build --force-recreate --wait` で反映する。
- 問題が出た場合は直前のworkerイメージへ戻し、失敗したMRは `/ai review` で手動再実行する。
- 再試行回数は既存の `AGENT_MAX_ATTEMPTS` を使用するため、環境変数で即時に調整できる。

## 7. 実装・検証結果（2026年8月24日）

- `REVIEW`／`RE_REVIEW` のCLI出力を保存前に検証し、不正JSONまたは不正なFinding型の場合は
  `AGENT_MAX_ATTEMPTS` の上限まで再生成する実装を追加した。
- 再試行時はJSONエスケープと生JSON出力を明示する専用指示を付与する。ログにはイベント種別、
  試行回数、解析エラーのみを記録し、生出力は記録しない。
- 不正JSONから2回目の成功出力へ回復するケース、全試行失敗時にジョブを失敗扱いにするケース、
  Findingスキーマ不正のケースを自動テストに追加した。
- 全自動テストは **98 passed**。既存依存ライブラリ由来の非推奨警告が1件あるが、テスト失敗はない。
- workerイメージを再構築してデモ環境へ反映し、既存のMR !12で `/ai review` を実行した。Claude CLIの
  正常JSON出力をFindingとして保存し、GitLab Discussion 3件と通常Note 1件の投稿を確認した。

> 実Claude出力を意図的に不正JSONにすることはできないため、再試行分岐そのものは自動テストで
> 検証した。実環境では通常JSONのレビュー完走を確認済みである。
