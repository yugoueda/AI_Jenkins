# デモ環境の再開・停止手順

GitLab.comのMerge Requestを起点に、Webhook、Jenkins、workerを動かすデモ環境の
再開手順です。`.env`とDocker named volumeが残っていれば、通常はイメージの再構築や
Claude Codeへの再ログインは不要です。

以下の手順は`scripts/demo-env.sh`にまとめてあります。個別コマンドを手で打つ代わりに
このスクリプトを使えます。

```bash
./scripts/demo-env.sh {up|rebuild|jobs|status|logs|down}
```

## 通常の再開

Docker EngineまたはDocker Desktopを起動し、リポジトリのルートで実行します。

```bash
./scripts/demo-env.sh up
```

内部では次を順番に実行します。

```bash
docker compose config --quiet
docker compose --profile agent up -d --no-build --wait
docker compose ps
./scripts/claude-login.sh status
```

Jenkins、webhook、workerが`healthy`になれば起動完了です。Webビルドに使う標準Flutter
イメージはJenkins専用DinDのnamed volumeに保持されます。`demo-env.sh up`はイメージの
有無を確認し、無ければ自動で取得します（手動で行う場合は下記）。

```bash
docker compose exec -T jenkins \
  docker pull ghcr.io/cirruslabs/flutter:stable
```

現在のビルド対象はFlutter Webのみです。Jenkinsは対象リポジトリで次を実行します。

```bash
flutter pub get && flutter build web
```

## イメージまたはジョブ定義を更新した場合

Jenkins、worker、webhookのDockerfileや依存関係を変更した場合だけ、対象イメージを
再構築します。

```bash
./scripts/demo-env.sh rebuild
```

内部では次を順番に実行します。

```bash
./scripts/jenkins-image.sh build
./scripts/agent-image.sh build
docker compose --profile agent up -d --no-build --force-recreate --wait
```

Jenkinsのデータはnamed volumeに永続化されます。`jenkins/Jenkinsfile.*`または
`jenkins/init.groovy.d/create-ai-review-jobs.groovy`を変更した場合は、起動後にジョブ
定義も更新します。

```bash
./scripts/demo-env.sh jobs
```

これは内部で`./scripts/refresh-jenkins-jobs.sh`を呼び、`.env`の`JENKINS_USER`と
`JENKINS_TOKEN`を使用します。値をコマンドラインへ直接書かないでください。

## ngrokとGitLab Webhook

ホストへngrokを導入・認証済みの場合、Webhookコンテナ起動後に別ターミナルで実行します。

```bash
./scripts/demo-env.sh ngrok
```

内部では`ngrok http http://127.0.0.1:8000`を実行します。

GitLabに登録するURLは、ngrokが表示したHTTPS URLへ`/webhook`を加えたものです。

```text
https://<ngrok-domain>/webhook
```

無料枠などでドメインが変わった場合は、GitLabプロジェクトのWebhook URLを更新します。
Secret Tokenには`.env`の`GITLAB_WEBHOOK_SECRET`と同じ値を設定し、SSL verificationを
有効にします。MR作成と`/ai`コマンドを処理するため、Merge request eventsと
Note eventsの両方を有効にします。

## 疎通確認とログ

```bash
./scripts/demo-env.sh status
./scripts/demo-env.sh logs
```

内部では次を実行します。

```bash
curl --fail --silent http://127.0.0.1:8000/healthz
curl --fail --silent --output /dev/null http://127.0.0.1:8080/login
docker compose --profile agent logs --tail=100 jenkins webhook worker
```

Webhookイベントを再送する前に、Jenkinsとwebhookが`healthy`で、workerが起動している
ことを確認します。MRを作り直す必要はなく、既存MRのWebhookをGitLab画面から再送して
試験できます。

## 停止

最初にngrokを実行しているターミナルで`Ctrl-C`を押し、外部公開を止めます。その後、
Composeコンテナを停止・削除します。

```bash
./scripts/demo-env.sh down
```

内部では`docker compose --profile agent down`を実行します。この操作ではJenkins設定、
ジョブ、Claude Code認証、データベース、Flutterイメージのnamed volumeは保持されます。
次回は「通常の再開」のコマンドで再利用できます。

`docker compose down -v`は永続データを削除するため、通常は実行しないでください。
