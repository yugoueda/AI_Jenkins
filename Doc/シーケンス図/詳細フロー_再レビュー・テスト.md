# 詳細フロー: 指摘対応後のテスト生成

以下は現行デモで成立している経路を示す。全Discussion Resolveを起点とする自動再レビューは、GitLab.comの実Webhookに`blocking_discussions_resolved`が含まれなかったため、実用化TODOとして本図から分離する。

```mermaid
sequenceDiagram
    participant User
    participant GitLab
    participant Webhook as Webhook受信サーバー
    participant DB as DB
    participant Jenkins
    participant Agent as エージェント連携
    participant Claude as ClaudeCode

    User->>GitLab: /ai approve ID または /ai reject ID
    GitLab->>Webhook: Note Hook
    Webhook->>DB: FindingをAPPLIEDまたはREJECTEDへ更新
    Webhook->>DB: OPENなAI指摘が0件か確認
    Webhook->>Jenkins: テスト生成前Build/Lintを実行
    Jenkins-->>Webhook: ビルド結果通知
    alt ビルド失敗
        Webhook->>Agent: BUILD_FIXジョブ登録（ビルドエラー）
        Agent-->>GitLab: ビルドエラー修正提案コメント
    else ビルド成功
        Webhook->>Jenkins: 静的解析ジョブ再実行
        Jenkins-->>Webhook: 静的解析結果通知
        alt 静的解析失敗
            Webhook-->>GitLab: 静的解析エラーコメント
        else 静的解析成功
            Webhook->>DB: UNIT_TEST_GENジョブ登録
            Agent->>Claude: ユニットテスト生成プロンプト送信
            Claude-->>Agent: パスコメント付きDartテストソース
            Agent->>GitLab: 生成テストをソースブランチへコミット
            Agent->>Jenkins: テスト実行ジョブ起動
            Jenkins-->>Webhook: テスト/カバレッジ結果通知
            alt テスト成功またはカバレッジ未達
                Webhook-->>GitLab: 実行結果とC0/C1をコメント
            else テスト実行失敗
                Jenkins->>Jenkins: テスト実行リトライ（1回）
                Webhook-->>GitLab: 再失敗結果とログをコメント
            end
        end
    end
```

手動修正またはDiscussion Resolve後は、利用者が`/ai review`で確認し、問題がなければ`/ai test`で上図のテスト生成処理を開始する。将来はDiscussion APIによる全Resolve再確認、Build/Lint、`RE_REVIEW`を接続し、再レビュー指摘が0件の場合だけ`UNIT_TEST_GEN`へ進める。
